# Feature spec 45: cyclic enum `Std.string` recursion

## Scope

The five generated targets previously expanded payload enum arguments while
emitting `Std.string`. A constructor argument whose type graph returned to the
enum (directly, through another enum, or through an array or supported sorted
collection) caused unbounded macro-time recursion and a compiler stack overflow.

## Ruling

1. `EnumCycleDetector.isCyclic` follows constructor argument types, unwraps
   abstracts including `Null`, and traverses payload enums and supported
   containers. Results are memoized and the active traversal set prevents a
   repeated enum from being expanded indefinitely.
2. A cyclic payload enum is rendered by a deterministic named runtime helper.
   The helper contains one arm per constructor and recursively calls itself for
   recursive operands; arrays and sorted collections retain their existing
   comma-separated runtime loops. Mutual enum cycles use one helper per enum.
3. Non-cyclic enums retain the existing inline `payloadEnumString` path and
   therefore preserve generated bytes.
4. The sample is `boring.StdStringSelfRecOps.SelfRecMark`, with plain, direct
   recursive, and array-recursive constructors. `tests.StdStringSelfRecTests`
   checks nested values and array separators in all eight generated examples.

## Sample

`StdStringSelfRecOps.markText` calls `Std.string` on `SelfRecMark`; the test
covers `plain`, two nested `wrap` values, and `nest([plain, wrap(plain)])`.
