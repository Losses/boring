RESOLVED 2026-11-04 — the nullable write projection. The family is fixed at
45f486db: `SemanticPolicy.nullableProjection` declares how an `Option` is
crossed, `classifyRoot` derives place-ness from that declaration instead of
hardcoding it, and a missing declaration fails closed. Readings on the pinned
artifact (no `--override-input`) are in §8. The bullets below stay as the record
of what the measurements looked like before the fix.

- Gate table (11 targets x 6 layers): 8 targets PASS, 3 with readings that
  are now real numbers rather than "unmeasured".

  engine-rust-f32, measured on `b322a232` with `--test-threads=1`:
  1319 passed, 29 failed (111.85s). The 29 are 22 `RefCell already borrowed`,
  3 trace assertions, 1 `Option::unwrap` on None. This reading only became
  possible after passing the deadlock below in the *generated* tree; the
  generated-code workaround is not a product fix.

  The deadlock is a codegen defect, reported with a stack and a 30-line
  reproducer that does not involve tiqian: a `MutexGuard` inside a `for`
  range expression lives for the whole loop body (Rust extends temporaries
  there), so the loop body's second `lock()` on the same mutex self-deadlocks
  (`plan_json_number.rs:181/183`). Every rust target that reaches such a
  loop never finishes its test layer, which is why these three targets looked
  unmeasurable. Fix belongs in the emitter: evaluate the range bounds into
  `let` bindings before the loop.

  engine-rust-f64 and protocol-rust were not re-measured after this finding;
  their earlier red described generated trees written 19+ hours earlier and is
  void. kotlin-f32 / kotlin-f64 / dart were red for the same staleness and
  turned green only after regeneration, so their earlier red is void too.

  Two measurement defects of ours, fixed in the harness and worth keeping:
  a reading must name the tree revision and the generated directory it tested,
  must capture the exit status without a pipe, and must run the suite with
  `--test-threads=1` (parallel execution trips the SingleThread guard and
  produces 1310 cascading PoisonErrors that look like failures but are not).
- RPlan wiring: `wire/rplan-product` on top of e63ae4fb; step 1 (contract
  types copied in, still green) not yet reported. RPlan is a release blocker.
- `t-mvvj76z6-nj0d` (P-21): deliverable landed, task status cannot be closed

## 5. Rules this release is judged by

- A: an observation whose opposite hypothesis gives the same result is a
  control group, not evidence.
- B: artifact provenance and tree provenance must both be recorded, or a red
  result is not reproducible.
- C: assertion outcome and process outcome are separate readings.
- D: zero subjects tested is not zero failures; a layer that collected no
  cases is UNMEASURED.
- E: when a new mechanism's inputs are supplied entirely by the old predicate,
  equivalence is constructive — but then the change is a refactor, not a policy
  change, and the release note must say which one it is.

implies representation policy changed would be wrong.
