## 4. What is the single highest-value next action, and what must become true for it to count as done?

**Assign package A to complete one frozen P08 implementation of the ordinary Swift read-only-array boundary using the already approved P07 producer design.** This requires an explicit current assignment because the owner stopped J1. Suspend unrelated additions to that candidate while this acceptance cycle runs. Supporting baseline and harness work may continue in isolated candidates.

I choose this action because it converts an already specified, demonstrably incomplete mechanism into an acceptance outcome. Commissioning another general architecture consultation or repeatedly correcting the policy record would leave the principal missing result unchanged.

It counts as done only when:

1. **The scope and bytes are fixed.** A named candidate contains the complete change and required harness dependencies. Its identity includes all consumed working bytes. The coordinator distinguishes P08's mechanism acceptance from P09's subsequent whole-system regression and identifies the finite remaining expanded-programme obligations.
2. **The existing semantic ruling is implemented.** Ordinary conversion preserves shared storage, retained-alias visibility, lifetime, and single evaluation. Optional values, literal forms, defaults, and reverse conversions have explicit, justified outcomes. Existing accepted source forms cannot be excluded merely because their producer is inconvenient.
3. **All eleven producer families in the approved inventory are accounted for.** Reads, construction, ordinary/replaced calls, casts, conditional/nil-merge/default results, block tails, switch/pattern results, try results, and nested elements return actual produced facts. Declarations remain stable across assignments; each result uses its actual destination, including when it differs from the enclosing function return type.
4. **The migration is demonstrably complete within that scope.** Every consumer is traced, including wrappers, direct declaration calls, and alternate statement routes. Superseded storage guesses and duplicate authorities are removed or adapted under an explicit compatible contract. Multiple callers of one planner are acceptable; incomplete or guessed facts at those callers are not.
5. **Fresh discriminating execution passes.** Construct or merge, bind, then pass or return through a typed consumer. Exercise both branch selections, nullable/default combinations, alias mutation after conversion, escaped lifetime, evaluation order/count, and lazy effects. Relevant native compilation and execution pass without generated-code warnings. Mutation controls operate on isolated inputs and preserve candidate identity.
6. **Independent acceptance is recorded against those same bytes.** Behaviour/oracle review and implementation review both accept the complete inventory and raw evidence. The coordinator records P08's outcome and explicit residual scope. A revised draft or a successful planner-only probe does not count.

This closes a bounded implementation milestone; it does not declare P09 or P12 passed. P09 then requires the same candidate's mandatory Boring checks and the fixed Tiqian pair, retaining all twelve generation and eleven target-test obligations and their comparison domains. Baseline failures and evidence-integrity defects remain prerequisites for that release-level closure.

## 5. What would I tell the person running this programme that they are least likely to want to hear?

**The coordinator's control of completion is part of the defect.** The programme's own retrospective admits that implementation proceeded without enforcing a requirement already known to matter. Repeated reports show agents departing from instructions that were already explicit. More wording, another model, and another independent reader will not by themselves convert that pattern into an accepted implementation.

You have obtained useful code, diagnoses, and infrastructure. You have not yet obtained the outcome the gates measure. Fifty-plus rounds, if that count is accurate, are a cost measure. A patch in scratch, a green compile with warnings, or a document that now accurately lists its defects cannot be counted as delivery of the intended architecture.

You also cannot simultaneously require a bounded local change and expect it to erase an unrelated red whole-system baseline without budgeting that baseline work. The current rules make those failures binding. Either fund their repair and enforce a stable candidate, or explicitly revise the programme's acceptance contract and publish what the narrower milestone means. The present process leaves that decision implicit.

Finally, pressure to close a gate is not evidence that the reviewer is too strict. The counterexamples are concrete. Accepting known missing producers as “individually ruled on” could make the paperwork pass while preserving the architecture contradiction. The hard decision is to stop adding activity until one finite acceptance unit is actually finished.
